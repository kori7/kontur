Задача 3. Платформа «Башкирская языковая
школа» (парные переводы с геймификацией)
Техническое задание к хакатону
Формат сдачи: веб-платформа + Telegram-бот + база переводов.
1. Общие положения
Задача — разработать платформу с элементами геймификации для составления
парных переводов башкирского языка с другими языками (аналог «башкирского
Duolingo»). Платформа позволяет пользователям ежедневно работать с
фрагментами текстов на башкирском языке, подтверждать или исправлять
переводы, и накапливает собранные переводы в своей базе данных.
Целевая аудитория — школьники и студенты башкирских учебных заведений,
преподаватели, носители языка и все желающие.
2. Цель и задачи
 •  Сохранение и популяризация башкирского языка через регулярную
интегрированную практику.
•  Накопление базы подтверждённых переводов для различных языковых пар.
•  Внедрение цифрового продукта в процесс обучения башкирских школ.
•  Вовлечение сообщества через рейтинги, соревнования и геймификацию.
3. Исходные данные
 •  Текстовые материалы на башкирском языке: художественные произведения,
общественно-политическая повестка, новости, учебные тексты.
•  Аудиоматериалы: аудиокниги, радио- и телепередачи на башкирском языке.
Платформа нарезает исходные материалы на осмысленные фрагменты, сохраняя
точные координаты источника (откуда взят фрагмент: произведение/файл, глава,
время в аудио).
4. Функциональные требования
4.1. Пользователи и регистрация
 •  Регистрация самостоятельно (через сайт или Telegram-бота) либо
преподавателем (учебное заведение, класс).
•  Выбор языковой пары, с которой работает пользователь (например,
башкирский ↔ русский, башкирский ↔ казахский и др.).
•  Профиль пользователя: языковые пары, статистика, достижения.
4.2. Нарезка материалов
 •  Разбиение текста на осмысленные фрагменты (абзацы/предложения, для
аудио — отрезки по времени).
•  Сохранение координат источника каждого фрагмента.
•  Двуязычное представление: башкирский фрагмент + автоперевод на
выбранную языковую пару.

4.3. Ежедневное задание
 •  Пользователю ежедневно предлагается фрагмент на башкирском языке и
автоперевод.
•  Иногда в автоперевод подмешивается заведомо ошибочный вариант.
•  Задача пользователя — подтвердить корректный перевод или исправить его
на правильный.
•  Опционально — синтез озвучки фрагмента (TTS) для аудиального восприятия.
4.4. Согласование переводов
 •  Платформа сопоставляет результаты по каждому фрагменту между
множеством пользователей.
•  На основе оценки большинства фиксируется корректный вариант с учётом
синонимичности.
•  Спорные случаи (нет консенсуса) направляются экспертам на решение (УФИЦ
РАН).
4.5. Рейтинги и геймификация
 •  Конкуренция между школами и классами.
•  Рейтинг по словарному запасу.
•  Самый активный за день / неделю / месяц / год.
•  Меньше всего ошибок и больше исправлений и т.д.
•  Баллы, уровни, достижения (бейджи), мотивационные элементы.
5. Накопление переводов (база данных)
Каждый подтверждённый или исправленный перевод сохраняется в базе данных
платформы вместе с привязкой к фрагменту. Это накопленный результат работы
пользователей: он растёт по мере использования платформы и остаётся внутри
неё.
Состав сохраняемой записи:
Поле
Описание
fragment_id
Идентификатор фрагмента
text_ba
Фрагмент на башкирском
lang_pair
Языковая пара (например, ba-ru)
translation
Подтверждённый/исправленный перевод
source
Координаты источника (документ/файл, глава, время)
confirmed
Число пользователей, подтвердивших вариант
status
confirmed / expert_review
Собранные переводы можно выгрузить для дальнейшего использования
заказчиком (школы, Фонд башкирского языка). Спорные случаи, требующие
решения экспертов (УФИЦ РАН), формируются в отдельный список — это задел на
развитие, не обязательный квант хакатона.
6. Интеграция (главное требование)

Проблема многих языковых проектов — результат нельзя «прикрутить» к
существующей системе. Поэтому данные и собранные переводы сохраняются в
документированной структуре и доступны через API:
 •  REST API для чтения фрагментов, сохранения ответов и выгрузки собранных
переводов.
•  Единая схема данных (см. п.5), не зависящая от конкретной команды.
•  LMS-совместимость: готовность встраивания в учебный процесс (отчёты
преподавателю по классу).
•  Инструкция по развёртыванию.
7. Требования к реализации
 •  Платформа: веб-сайт + Telegram-бот (основные каналы); интеграция в MAX —
опционально, не обязательна.
•  Стек — на усмотрение команды; обязателен структурированный слой данных
(PostgreSQL) и API.
•  FSM-диалог бота для ежедневных заданий, состояния в БД, поддержка /start и
/cancel.
•  Хранение: пользователи, языковые пары, фрагменты, координаты источников,
ответы, рейтинги, подтверждённые переводы.
•  Обработка ошибок, логирование, защита пользовательского ввода.
•  Модерация спорных случаев: интерфейс/список для передачи экспертам.
8. Технические препятствия и допущения
 •  Качество автоматического машинного перевода башкирского ограничено;
подмешивание ошибок выполняется вручную/по правилам в MVP.
•  Синтез озвучки башкирского — предпочтительно использовать доступные
TTS; полный синтез на башкирском может быть ограничен и не обязателен.
•  Экспертная валидация (УФИЦ РАН) выносится за рамки хакатона;
фиксируются спорные случаи для последующей передачи.
•  Работа с реальными авторскими материалами — с учётом разрешения на
использование.
9. Критерии оценки
 •  Полный цикл: материалы → фрагменты → ежедневное задание → согласование
→ фиксация перевода.
•  Работоспособность геймификации и рейтингов.
•  Документированность структуры данных и API.
•  UX: аккуратный интерфейс, минимум действий, мотивация.
•  Устойчивость и стабильность.
10. Результат
 •  Работающая платформа (веб + Telegram-бот) с ежедневными заданиями и
рейтингами.
