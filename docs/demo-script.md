# Сценарий показа и репетиции

Документ для двух репетиций и самой защиты. Регламент (длительность, свой экран и роутер, проектор с выводом телефона) у организаторов ещё не уточнён (ответы §9) — тайминг ниже рассчитан на 7 минут показа и подгоняется, когда регламент будет известен.

Главное правило: **показываем только то, что работает вживую**. Критерий «Прототип» сравнивает заявленное с работающим (ответы §10). Всё, что ещё не готово, называем планом.

## Подготовка накануне

- [ ] Ноутбук-сервер заряжен, блок питания с собой. `.venv` с зависимостями детектора и обучения; веса в `.models/`.
- [ ] Свой роутер или точка доступа без выхода в интернет, если организаторы разрешат; иначе — Wi-Fi площадки. Проверить, что телефон и ноутбук видят друг друга.
- [ ] На телефоне установлен корневой сертификат (`http://<IP>:8080`), приложение открывается по `https://<IP>:8443`.
- [ ] Распечатан стенд A4 (`artifacts/stand.pdf` или `/stand.html`, масштаб 100%), второй экземпляр — запасной.
- [ ] Учётные записи: администратор, мастер, инженер. Пароли знает команда, в репозиторий не попадают.
- [ ] База показа чистая: отдельный `APP_DB_PATH`, в журнале нет тестовых записей.
- [ ] Презентация открывается на ноутбуке без сети (`/presentation.html`), запасная копия в PDF.

## Запуск в день защиты

Три окна терминала, в таком порядке:

```bash
.venv/bin/python scripts/dev/io-emulator.py --port 5020
```

```bash
KONTUR_IO=modbus://127.0.0.1:5020 KONTUR_DETECTOR=owlvit APP_DB_PATH=data/defence.db ./scripts/start-lan.sh
```

Когда будет дообученная модель — `KONTUR_DETECTOR=rfdetr` вместо `owlvit`. Затем на телефоне: войти инженером, проверить камеру на стенде.

## Если что-то пошло не так

| Сбой | Что делаем |
|---|---|
| Телефон не открывает приложение | Проверить сеть и сертификат; запасной путь — показать с ноутбука на `https://127.0.0.1:8443` с вебкамерой или по экрану |
| Камера не даёт разрешение | Настройки браузера → разрешения сайта; Safari: «аА» → «Настройки веб-сайта» |
| Табличка не читается | Подойти ближе, убрать блик; иначе QR — это штатный запасной путь, его и показываем |
| Сервер ввода/вывода не отвечает | Приложение само пишет «Сервер ввода/вывода … не отвечает» и показывает последнюю запись ряда. Перезапустить эмулятор |
| Детектор рисует лишние рамки | Говорим прямо: это модель без обучения, показываем механику подтверждения и «Не дефект». Не спорим с рамкой |
| Всё упало | PDF презентации и записи экрана с репетиции |

## Вопросы, к которым готовимся

- **Насколько точно распознаёт?** Детектор без обучения — нет, недостаточно, мы это измерили и не скрываем. Конвейер обучения готов, проверен от данных до рамки; нужны снимки объекта. Сверка правил с «Диагнозом» — 482/500 и 500/500.
- **Почему не YOLO?** Ultralytics YOLO под AGPL; заказчик просил лицензии, которые можно использовать везде. RF-DETR и OWL — Apache 2.0.
- **Откуда нормативы Wilo?** Узлы и требования — из РЭ Wilo-IL. Интервалов ТО в часах в РЭ нет: рубежи взяты из примера организатора и помечены «принято командой».
- **Что если нет связи с сервером?** Обход идёт в локальной сети предприятия (ответы §3). Без сети приложение явно говорит, что сервер недоступен, и ничего не выдумывает.
- **Как внедрять на объекте?** Локальный сервер, Wi-Fi цеха, телефоны персонала; адаптер к серверу ввода/вывода по Modbus уже есть, OPC UA — следующий шаг; детектор дообучается на снимках объекта.
