# КОНТУР

Демонстрационный помощник инженера для осмотра насосного агрегата Н-101. Он соединяет цифровую карточку, временные ряды датчиков, визуальные наблюдения, объяснимые правила и журнал работ. Решение о состоянии оборудования принимает инженер.

В MVP входят один агрегат, 12 правил, 14 воспроизводимых сценариев (`normal`, `r01`–`r12`, `missing_data`), просмотр узлов, снимок/камера, QR, маркерный AR и сохранение истории в SQLite. Все исходные характеристики, измерения и нормативы синтетические. Отсутствие предупреждений не подтверждает исправность насоса.

## Быстрый запуск на Windows

Требуются Node.js 24, npm 11, Python 3.11 и PowerShell 5.1. Docker не нужен. Выполняйте команды из корня проекта. Зависимости устанавливаются из сети при первом запуске.

```powershell
python -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install -r requirements.txt
npm ci
npm run build
& ".\scripts\start.ps1"
```

Откройте [приложение](http://127.0.0.1:8000), [презентацию из 7 слайдов](http://127.0.0.1:8000/presentation.html) или [стенд для печати](http://127.0.0.1:8000/stand.html). Скрипт держит сервер в текущем терминале. Для остановки нажмите `Ctrl+C`.

Презентация переключается стрелками, `Home` и `End`. Кнопка «Печать / PDF» выводит все слайды. Файл `apps/web/public/presentation.html` также открывается напрямую в браузере.

### Режим разработки

В первом терминале:

```powershell
& ".\scripts\start.ps1" -Dev
```

Во втором терминале из корня проекта:

```powershell
npm run dev
```

Интерфейс доступен на [127.0.0.1:5173](http://127.0.0.1:5173). Vite направляет запросы `/api` на порт 8000. Эквивалент прямого запуска API:

```powershell
& ".\.venv\Scripts\python.exe" -X utf8 -m uvicorn app.main:create_app --factory --app-dir services/api --host 127.0.0.1 --port 8000
```

После изменения фронтенда перед запуском собранной версии повторите `npm run build`. API также предоставляет [OpenAPI-документацию](http://127.0.0.1:8000/docs).

## Визуальная модель

Серверный адаптер использует совместимый API `https://agentrouter.org/v1` и модель `gpt-6-astra`. Ключ читается из `VISION_API_KEY` или `AGENTROUTER_API_KEY`. Задайте его через окружение процесса либо пользовательские переменные Windows, затем перезапустите API. Не сохраняйте ключ в исходниках, документах или передаваемом архиве.

Несекретные параметры находятся в `.env.example`: `VISION_BASE_URL`, `VISION_MODEL`, `APP_DB_PATH`. Скрипт запуска переносит пользовательскую переменную ключа в окружение сервера, если соответствующая переменная процесса ещё не задана. Признак `vision.configured` означает наличие ключа, а не успешную авторизацию у провайдера.

**Статус проверки доступа:** запрос `GET /v1/models` вернул HTTP 401 с сообщением `unauthorized client detected`. Шлюз отклонил API-клиент. Новый `VISION_API_KEY` успешно прочитан из пользовательского окружения Windows без пробельных символов, поэтому ответ не доказывает невалидность ключа. Нужен разрешённый шлюзом доступ для собственного API-клиента; повторная смена ключа не подтверждена как решение. Успешный живой анализ пока не подтверждён. Демосценарии и ручные наблюдения доступны независимо от модели.

При нажатии «Анализировать» снимок отправляется во внешний сервис. Адаптер принимает только наблюдения `guard_missing`, `liquid_leak`, `missing_bolt`, качество снимка, пояснение и необязательные области `bbox`. Качество `good` позволяет использовать наблюдение, `limited` требует дополнительной проверки, `unreadable` исключает наблюдения. Процент уверенности не выдумывается. Некорректный ответ не превращается в диагноз. Приложение не измеряет температуру RGB-камерой.

## Камера и AR

Камере нужен защищённый контекст: HTTPS либо `localhost` на самом устройстве. Адрес `http://192.168.…` в локальной сети не даёт обычному браузеру телефона доступ к камере. Для проверки на телефоне потребуется доверенный HTTPS-адрес и разрешение камеры. Обнаружение маркера и скрытие меток после его потери проверены в браузере на поданном видеопотоке печатного стенда. Физический телефон и реальные условия съёмки ещё не проверены.

QR со значением `kontur:pump-101` идентифицирует единственный агрегат. Hiro задаёт положение схемы на печатном стенде. Это разные маркеры. AR.js и A-Frame поставляются в `apps/web/public/vendor`; все 10 компонентов карточки представлены AR-метками с заданным положением относительно стенда. Система не локализует детали произвольного насоса. При потере Hiro метки скрываются. Рамки модели относятся только к проанализированному снимку.

## Проверки

Основная проверка запускает Python-тесты, Ruff и сборку TypeScript/Vite:

```powershell
& ".\scripts\check.ps1"
```

Для браузерных проверок сначала запустите API на порту 8000 и Vite на 5173. Установите Chromium один раз, затем выполните:

```powershell
npx playwright install chromium
& ".\scripts\check.ps1" -Browser
```

Отдельные команды:

```powershell
& ".\.venv\Scripts\python.exe" -X utf8 -m pytest -q
& ".\.venv\Scripts\python.exe" -X utf8 -m ruff check services tests scripts
npm run build
npm run test:ui
```

Автотесты правил и адаптера проверяют поведение кода, в том числе отказы и неполные данные. Они не доказывают точность диагностики, успешность внешнего API или работоспособность камеры на физическом телефоне. Матрица объёма и оставшихся проверок: [docs/coverage.md](docs/coverage.md).

## Данные и передача проекта

- `apps/web` — React + TypeScript + Vite, презентация и печатный стенд.
- `services/api/app` — FastAPI, диагностические правила, модель и SQLite.
- `tests` — проверки API, хранения, правил, адаптера и пользовательских сценариев.
- `docs` — [архитектура](docs/architecture.md), [сценарий показа](docs/demo-guide.md), [покрытие](docs/coverage.md), [инвентаризация материалов](docs/stage-a-inventory.md), [контракты](docs/contracts.md).
- `data/registry` — реестр этапа A: классификация переданных файлов, типы оборудования, объекты, классы дефектов и источники измерений.
- `data/inspection.db` — создаваемая при запуске локальная база. Путь можно изменить через `APP_DB_PATH`.

В базе сохраняются входы и результаты анализа, переданные на сервер снимки и записи проверки, замечания, обслуживания и замены. Одинаковые изображения хранятся один раз. Журнал позволяет открыть снимок соответствующего осмотра через `/api/images/{image_id}`. Приложение добавляет записи без редактирования предыдущих и возвращает всю историю. Это история приложения, а не защищённый от администратора аудит.

В карточке заменённого узла нормативный остаток пересчитывается от наработки на момент замены. Замена одного узла не обнуляет ресурс остальных. Если текущая наработка или опорная наработка неизвестна, результат остаётся неизвестным. Нормативный остаток не является прогнозом времени до отказа.

Для передачи достаточно исходников, `package-lock.json`, `requirements.txt` и документации. `.venv`, `node_modules`, локальный `.env`, ключи и персональную базу передавать не нужно. Синтетические SVG в `public/demo` — собственные схемы проекта, а не фотографии реальных дефектов. Сведения об их происхождении указаны в `public/demo/manifest.json`.

Перед промышленным использованием необходимы нормативы изготовителя, реальные синхронизированные данные, размеченный набор дефектов, проверка качества модели и AR, авторизация пользователей и эксплуатационная защита сервиса. Приложение не управляет оборудованием и не выдаёт прогноз времени до отказа.
